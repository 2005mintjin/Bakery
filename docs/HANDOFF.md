# 개발 인계 · 마을회관과 조합 등급

## 작업 기준

현재 체크아웃의 `demo` 브랜치에서 검토한다. 정식 배포 요청은 없으며 main/gh-pages를 변경하거나 웹사이트를 게시하지 않는다. 데모는 5174·saves-demo·별도 브라우저 저장 키를 사용한다. 기존 정식 저장을 자동 복사하거나 삭제하지 않는다. 작업 환경은 이미 격리되어 있으므로 별도 worktree를 만들지 않는다.

이전 채팅 링크의 대화 본문은 직접 확인하지 못했다. 이 문서는 현재 저장소와 이번 채팅에서 전달받은 요구사항·첨부 자료를 근거로 작성했다.

## 이번 요구사항과 구현

- `Downloads (14).zip`의 마을회관 원본 그림으로 소도시 왼쪽 아래 건물 내부를 구현했다. 카운터 너머 분홍머리 로터스, 앞 왼쪽 하얀 머리 헨델, 앞 오른쪽 모자를 쓴 아델은 배경에 이미 있으므로 중복해서 그리지 않는다.
- 네 인물의 원본 SD·상반신 PNG·MP3를 이름별로 보관했다. 회관은 원본 배경 인물, 대화는 원본 상반신, 실외 마틴은 SD를 사용한다. 목소리는 기존 글자별 재생·공통 음량·무음·취소 규칙을 따른다.
- 하린은 마틴으로 교체했으며 기존 실외 ID `artist`는 유지한다. 첨부 TXT의 대사·선택지를 데이터로 구성했다. 나레이션은 별도 페이지이며 무음이다.
- 마틴의 부탁은 수락 → 마리아에게 전달 → 마틴에게 돌아가 보고 → 완료 순서다. 전달 전 거짓 보고를 해도 선물은 남는다. 마리아에게 누구의 선물이라고 말하든 실제 전달된다. 선물 선택지는 마리아의 기존 꿀빵 부탁 상태와 무관하게 표시된다. 선물은 가방의 소모 재료가 아닌 퀘스트 상태로 보관하며 임의 골드 보상은 추가하지 않았다.
- 로터스에게 좋아하는 빵을 물어본 뒤 베리 빵 선물이 열린다. 가방에 빵이 없으면 버튼이 비활성화된다. 대사를 끝까지 읽어야 1개를 소비한다. 선물은 조합 평가를 올리지 않는다.
- 아델에게 조합 등급, 평가 기준, 다음 평가일, 현재 지원품을 확인할 수 있다. 기존 우체국 소포에 등급별 지원을 적용했다.

## 조합 규칙과 선택한 기본값

게임 1일째를 월요일로 두고 매주 월요일 06:00에 직전 7영업일의 실제 판매 개수를 7로 나눈다. 영업일은 06:00부터 다음 날 06:00까지다. 휴업일은 0개로 포함한다. 평가 후 달성 등급은 유지한다. 판매한 모든 제빵 제품의 수량을 세며, 매출 골드·퀘스트 전달·선물·진열만으로는 판매량이 오르지 않는다.

| 등급 | 일평균 판매 기준 | 매일 지원품 |
| --- | --- | --- |
| D | 시작 등급 | 밀가루 4, 꿀 1 |
| C | 5개 이상 | 밀가루 8, 꿀 2, 이스트 2, 소금 2 |
| B | 10개 이상 | 밀가루 12, 꿀 3, 이스트 4, 소금 4, 버터 2, 설탕 2 |

등급 기준·지원량은 `src/guild.js`의 guildRules에서 조정한다. 시작 요일·기준 수량·등급 유지 정책은 사용자가 숫자를 지정하지 않아 이번 구현에서 선택한 기본값이다. 처음 평가는 8일째다. 소포의 기존 하루 한 번 수령 규칙은 유지하며 당일 승급해도 재수령할 수 없다.

## 저장 호환과 담당 파일

저장 v8의 선택 필드 `civic`과 `guild`를 추가했다. 기존 돈·아이템·진행·호감도를 유지한다. 예전 세이브는 읽은 영업일부터 판매량을 기록하며, 과거 누적 매출에서 판매 개수를 추정하지 않는다. 이관한 주가 불완전하면 그 주는 평가하지 않고 다음 완전한 주를 기다린다.

- `data/civicStories.json`, `data/civicActors.json`, `data/source/*-dialogue.txt`: 원문·대사·선택지·배역.
- `src/civicStory.js`: 회관 대화, 선물 전달/보고와 로터스 선물. 완료 콜백은 재고/단계를 재검사하고 중복 실행을 막는다. ESC 취소 시 정산하지 않는다.
- `src/townStory.js`, `data/townStories.json`: 마리아의 기존 부탁과 새 선물 선택지, 추가 일상 대화.
- `src/guild.js`, `src/dailyReport.js`, `src/wellbeing.js`, `src/shop.js`: 판매 기록·월요일 평가·시계 점프·소포 지원.
- `src/save/civicState.js`: 새 저장 필드의 이관과 검증.
- `data/worldMaps.json`, `src/interior.js`, `src/renderer.js`: 회관 출입·배경·실내 버튼. 회관 앞 기존 건물 충돌 영역도 출입구 높이에 맞췄다.

## 실행과 검증

Node.js 20 이상에서 패키지 설치 없이 `npm start`로 실행한다. 데모 서버는 5174에서 실행된다. 검사에는 개인 세이브를 사용하지 않는다.

```sh
npm test
npm run check
BAKERY_PLAYWRIGHT_MODULE=file:///opt/codex/cua_node/lib/node_modules/playwright/index.mjs BAKERY_BROWSER=/usr/bin/chromium node tools/check-civic-browser.mjs
```

브라우저 도구는 정적 빌드와 임시 호스트·격리 브라우저 저장을 사용한다. 다른 정적 브라우저 도구와 동시에 실행하지 않는다. 제한된 실행 샌드박스에서 로컬 포트나 Chromium 실행이 거부되면 지원되는 실행 권한으로 검사하며 앱 보안을 바꾸지 않는다. Windows 직접 실행과 실제 휴대폰·Safari 검사는 별도다. 최종 검사 결과는 완료 보고를 참고한다.

최종 검증: 전체 테스트 154개 모두 통과, JavaScript 153개 구문 검사 통과. `check-civic-browser.mjs`에서 회관 출입·원본 배경/초상·네 음원 디코딩과 실제 재생·로터스 선물 조건·헨델 대화·실제 판매 후 월요일 A 승급·마틴/마리아 전달 및 보고·저장 재접속·A 지원품의 당일 중복 방지·390px 화면을 통과했다. `check-web-browser.mjs`에서 기존 웹 경로·PC 이동·저장/재접속·JSON 이동·삭제/취소·격리를 통과했다. 이미지/음원 13개는 첨부 원본과 SHA-256이 동일하다. 데모 개발 서버 시작도 확인했다. 정식 배포와 Windows 직접 실행·실물 모바일 검사는 수행하지 않았다.

## 후속 수정 · 음성 및 스프라이트 표시

`Downloads (15).zip`의 로터스.mp3·아델.mp3를 이름별로 재확인했다. 두 파일은 Downloads (14)에서 적용한 원본과 바이트까지 동일했다. 파일명 연결을 유지하고 PCM 원본을 수정하지 않았다. 로터스의 첫 글자 재생 구간은 실제 목소리보다 크게 조용한 시작 부분이었고, 아델의 샘플은 다른 인물보다 낮은 음량이었다. 두 인물에만 `sliceSelection: strongest`를 설정해 가장 에너지가 큰 28ms를 선택하고, 아델에는 개별 gain 3을 적용했다. 기존 공통 음량·음소거·구두점/나레이션 무음·대화 취소 규칙은 유지한다. `src/dialogueVoice.js`의 audibleWindow가 원본 디코딩 버퍼를 바꾸지 않고 구간만 선택한다.

마틴의 SD 높이를 70에서 96으로 늘렸다. 발 위치·원본 비율·상호작용 좌표는 유지한다. 월드 캔버스와 배경 버퍼는 1920×1152에서 2880×1728로 높였으며 논리 좌표는 기존 960×576을 유지한다. 원본 PNG를 작게 그리는 주민·플레이어·손님에 고품질 축소 필터를 적용하고, 월드와 대화 그림의 CSS 강제 pixelated 축소를 해제했다. 배경·도형의 기존 그리기 규칙은 유지한다.

관련 브라우저 픽셀 검사는 고정 2배 좌표 대신 실제 캔버스 크기에 따라 검사하도록 보완했다. `check-civic-browser`는 로터스와 아델 각각의 실제 자연스러운 대사 출력 중 해당 음성 버퍼의 재생 시작과 선택된 PCM 구간의 신호 크기를 확인한다. 가장 강한 구간 선택의 약한 시작음·스테레오·짧은 샘플은 단위 검사로 확인한다.

후속 수정 검증: 전체 테스트 156개와 JavaScript 153개 구문 검사 통과. 마을회관 브라우저 검사에서 로터스·아델 각각의 자연 출력 음성 버퍼 재생, 재생 구간의 음성 신호 크기, 2880×1728 캔버스, 확대된 마틴과 390px 대화 표시를 확인했다. 모바일 가로/세로·다중 터치·반죽·낚시·결산·저장 재접속 검사와 고해상도 손님 카운터 전경 픽셀 검사를 통과했다. 회관 검사와 카운터 검사는 개인 저장 파일을 사용하지 않는다. 이번 작업도 demo에만 반영한다.

## 정식 승격 · 사용자 사이트 반영 요청

사용자가 검토한 이번 버전을 사이트에 적용하도록 요청했다. `demo`의 회관·조합 등급·음성 보정·고해상도 표시를 정식 `main`으로 승격하고, edition=false·5173·saves·기존 little-hearth:web: 키를 복구한다. demo 브랜치의 true·5174·saves-demo는 별도로 유지하며 저장 파일을 자동 복사하거나 삭제하지 않는다.

정식 모드에서 전체 테스트 156개 중 155개 통과, 데모 배포 차단 전용 1개 제외, JavaScript 153개 구문 검사 통과. 정적 웹 브라우저 검사에서 기존 주소/저장 키·PC 이동·저장 재접속·JSON 이동·삭제 취소/격리를 확인했다. 배포에는 저장·서버·개발 파일이 제외되는 기존 `npm run publish:web` 명령을 사용한다. 게시 브랜치 업로드와 실제 GitHub Pages 배포 완료는 구분하여 최종 보고한다.

## 후속 작업 · 번화가 지도 2장 (데모)

이번 요청은 지도와 기본 NPC까지다. 새 기능은 `demo`에서 검토하며 이번 변경으로 정식 main/gh-pages를 갱신하지 않는다. 데모 모드 true·5174·saves-demo·별도 웹 저장 키를 유지한다.

`Downloads (16).zip`의 두 PNG를 원본 바이트로 보관했다. `픽셀 아트 마을 광장 풍경.png`는 `assets/backgrounds/downtown-services.png`로 먼저, 나머지 술집·24시 가게·수리점과 쉼터 그림은 `assets/backgrounds/downtown-square.png`로 다음에 나온다. 동선은 city → downtown → downtownEast이며 왼쪽으로 왕복 가능하다. 마지막 구역의 서쪽 출입구는 원본의 왼쪽 위 좁은 가로길에 맞춰 y=280으로 둔다. 병원·책방 거리로 되돌아올 때는 y=310이다. 각 구역의 safeSpawn은 [480,310]이다.

`data/worldMaps.json`에 원본 크기·배경·충돌·안전 위치를 정의하고, 새 구역의 doors는 비워 두었다. 건물·상점 기능은 구현하지 않았다. 첫 구역의 네 건물과 둘째 구역의 세 건물은 `data/downtown.json`에 available=false로 정리했다. `sceneManager.js`가 새 통로를, renderer/hud/hints가 장소·방향·준비 중 안내를 표시한다. `data/lighting.json`의 가로등은 원본의 가로등 위치에 맞춰 기존 야간 규칙을 적용한다.

주민은 첫 구역 세린·유진·소율, 둘째 구역 태오·나래·도윤으로 총 6명이다. 아직 캐릭터 전용 리소스가 제공되지 않아 `assets/characters/townsfolk/`의 간단한 기본 SVG를 SD와 대화에 함께 쓴다. 기존 named NPC의 초상·음성을 임의로 배정하지 않는다. 이름·좌표·색·대사는 `data/downtown.json`에 있으며 퀘스트나 판매 기능은 없다. `npc.residents`가 새 구역 주민을 선택하고, createGame이 리소스를 읽는다. line 대화는 해당 NPC의 portraitAsset을 전달하도록 보완했다.

저장 v8을 유지하며 validate에서 새 장면 두 개를 허용한다. 추가 진행 필드는 없고 돈·기존 부탁·물품·조합 기록을 바꾸지 않는다. 새 장면에서 저장하고 재접속할 수 있다. 구버전 세이브는 기존 규칙 그대로 읽는다. 이전 버전의 게임 프로그램은 새 장면을 모를 수 있으므로 새 구역 저장은 최신 데모에서 연다.

검사: `node --test tests/downtown.test.js`, `node tools/check-downtown-browser.mjs`. 브라우저 도구는 임시 정적 호스트·독립 브라우저 저장으로 키보드·실제 터치 왕복, 두 구역 저장/재접속, 여섯 주민 대화·본인 기본 초상, 원본 지도 순서·건물/울타리 충돌·야간 조명·390px 화면을 확인한다. 다른 정적 브라우저 도구와 순서대로 실행한다.

번화가 최종 검증: 전체 테스트 161개 통과, JavaScript 155개 구문 검사 통과. 번화가 전용 브라우저 검사에서 실제 키보드/터치 왕복·원본 지도 순서·두 장면의 저장 재접속·주민 6명의 대화/초상·건물/울타리 충돌·야간 조명·390px 화면을 통과했다. 지도 2장은 ZIP 원본과 SHA-256이 동일하다. 새 건물 내부·상점/병원/경찰/음반 기능과 개별 퀘스트는 구현하지 않았다. Windows 직접 실행과 실제 휴대폰 실기 검사는 별도다.

## 후속 수정 · 회관/마틴 방문과 무작위 방문 순환 (데모)

확인 결과 이전 회관 구현에는 주민/직원 대화·이미지·음성만 있고 빵집 방문 등록이 빠져 있었다. 사용자 지시에 따라 헨델·아델·마틴만 손님에 추가했으며, **로터스는 방문하지 않는다**. 기존 10명과 합쳐 방문 대상은 13명이다. 이번 범위에서 번화가의 기본 안내 주민 6명은 손님으로 추가하지 않았다.

`data/customers.json`에 각 원본 SD PNG의 알파 영역과 별도의 일반 초상을 등록했다. 새 세 인물은 dialogueUsesSprite를 설정하지 않아 카운터는 SD, 대화창은 일반 초상이 된다. 기존 목소리 매핑을 재사용한다. 헨델은 부드러운 존댓말·으음, 아델은 무뚝뚝한 반말·말줄임표, 마틴은 짧고 어순이 독특한 반말과 마리아 언급으로 `serviceDialogues.json`에 주문·감사·대기·거절 대사를 새로 작성했다. 마틴의 꿀빵 선호 가중치는 원문의 꿀빵 구매 언급을 따라 4다. 회관/선물 퀘스트 진행과 조합 등급은 손님 대사로 변경하지 않는다.

`src/visitorOrder.js`가 방문자 ID를 Fisher–Yates 방식으로 섞어 `shop.visitorQueue`에 보관하고 한 명씩 꺼낸다. 한 바퀴의 모두가 방문한 뒤 다시 섞으며, `shop.lastVisitor`로 바퀴 경계의 연속 재방문도 방지한다. `shop.sequence`는 누적 방문 횟수로 유지하지만 더 이상 순서를 결정하지 않는다. 기존 12초 방문 간격·노크·주문 수량·판매 정산은 유지한다. 영업 종료/거절은 큐를 초기화하지 않으며, 시작한 방문은 판매 여부와 무관하게 그 바퀴에서 방문한 것으로 센다.

저장 v8의 선택 필드 visitorQueue/lastVisitor를 검증한다. 중복 ID·알 수 없는 ID·로터스 ID는 거부한다. 기존 저장에 필드가 없으면 빈 큐를 보충하고 현재 대기 손님은 유지한다. 과거 방문 순서는 추정하지 않는다. 대기 손님이 있으면 마지막 방문자로 보충해 바로 재방문하지 않도록 한다. 미래에 손님을 추가할 때는 customers JSON과 visitorOrder의 허용 ID를 함께 갱신한다. 명단이 변경되어 이미 저장된 큐에 없는 새 인물은 다음 바퀴에 포함된다.

검증: 전체 테스트 166개 통과, JavaScript 158개 구문 검사 통과. 새 `tests/visitorOrder.test.js`가 여러 바퀴의 전체 방문·무중복·재섞기·경계 중복 방지·저장/영업 종료 후 큐 유지·이관·새 주문 정산을 검사한다. `tools/check-civic-visitors-browser.mjs`는 별도 정적 호스트와 브라우저 저장을 사용해 세 신규 손님의 실제 도착·카운터 전경 가림·일반 초상·음성 재생·대기/판매·주문/큐 저장 재접속·모바일 대화와 세 바퀴 무작위 순환을 확인한다. 정식 사이트 승격은 이번 요청 범위에 포함하지 않는다.

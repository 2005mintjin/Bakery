# 작은 화덕 · 달빛마을
빵집과 주민 이야기를 중심으로 하는 HTML5 픽셀 어드벤처입니다. 기존 런앤건 프로젝트와 독립적입니다.

## Windows 실행
1. 최초 한 번 Node.js LTS (20 이상)를 설치합니다.
2. 다운로드한 ZIP **전체를 압축 해제**합니다.
3. `launch.bat` 또는 `게임 실행.bat`을 더블클릭합니다. 준비 후 브라우저가 열립니다.
4. 종료할 때 서버 창에서 Ctrl+C를 누릅니다.

패키지 설치 없이 실행되며, `npm start`도 동일합니다. `index.html` 직접 열기는 지원하지 않습니다. 서버는 본인 PC의 127.0.0.1:5173에만 바인딩합니다. 구버전 서버 창이 열려 있으면 닫고 최신 폴더에서 다시 실행하세요. 배치 파일은 ASCII/CRLF이며 Node를 게임 폴더의 절대 경로로 호출합니다.

## 시작·저장
- 타이틀에서 세이브 1~3번 선택. 빈 슬롯을 고르면 파일을 만든 뒤 짧은 인트로가 나옵니다.
- **ESC → 저장**으로 게임 폴더의 `saves/slot-N.json`에 저장합니다. 자동 저장은 없습니다.
- 같은 폴더의 세이브는 브라우저를 바꿔도 불러옵니다. 다운로드한 새 버전으로 옮길 때 기존 `saves` 폴더를 복사하세요.
- 구버전 localStorage 저장은 타이틀의 이전 저장 옮기기로 빈 슬롯에 가져옵니다. 이전과 같은 브라우저/주소에서 실행해야 합니다.
- 타이틀로 돌아가면 저장하지 않은 진행을 잃습니다. 손상된 파일은 자동으로 덮어쓰지 않습니다. 백업을 복원하세요.
- 파일 저장은 Node 서버 API가 필요하므로 GitHub Pages 같은 정적 호스팅은 지원하지 않습니다.

## 조작과 플레이
실외에서는 WASD/방향키 이동, E 상호작용. 실내에서는 정면 1인칭 화면의 버튼을 클릭합니다. I 가방, J 부탁 수첩, ESC 메뉴는 공통입니다. 대사는 한 글자씩 출력합니다. **스페이스 / 다음**은 출력 중인 줄을 완성하고, 다시 누르면 다음 줄로 넘어갑니다. 마지막 줄 다음에는 선택지가 나타나며 클릭 또는 Tab/Enter로 고릅니다. ESC/닫기로 중간 취소할 수 있습니다. 메뉴/대화 중 시간과 손님 도착이 멈춥니다.

### 빵집 운영과 제빵
1. 빵집에 들어가 **작업실 →** 화살표를 누릅니다.
2. **화덕 · 빵 굽기 → 재료 섞어 반죽 시작**. 밀가루 2개, 이스트 1개, 소금 1개를 사용합니다.
3. 반죽 위에서 **마우스를 누른 채 좌우로 문질러 100%**까지 치댑니다. 마우스를 누르지 않은 이동은 반죽에 반영되지 않습니다. 화면 크기가 바뀌어도 좌표를 보정합니다.
4. 토핑을 하나 선택합니다. **없음 → 밀빵 / 꿀 1개 → 꿀빵 / 베리 2개 → 베리빵**. 고른 뒤에는 해당 반죽의 토핑을 바꾸지 않습니다.
5. **오븐에 넣고 굽기**를 누르면 5초 후 완성됩니다. 다른 메뉴나 장소에서도 굽기는 계속되고, 숨겨진 탭에서는 멈춥니다.
6. **완성한 빵 꺼내기**를 누르면 빵 창고로 옮겨집니다. 창고에서 꺼낸 뒤 판매실의 진열대에 올립니다.
7. 진열장에는 종류별 빵 일러스트와 수량이 표시됩니다(각 종류 최대 4개 그림, 실제 수량은 별도 표시).
8. **영업 안내판**에서 개점합니다. 플레이 시간 12초가 지나면 손님이 세 번 노크하고, 약 1.2초 뒤 계산대 너머에 큰 상반신 모습으로 나타납니다. 계산대 앞면이 몸 아래쪽을 가립니다. **손님과 대화하기** 버튼을 눌러 말투가 다른 주문을 듣고 답합니다. 진열대는 빵을 놓는 용도로 사용합니다.

한 번에 손님 한 명이 기다립니다. 대화에서 **네, 금방 갖다 드릴게요!**를 선택하면 진열된 주문 빵을 건네고 정산합니다. 진열된 빵이 없으면 판매하지 않고 준비 안내를 보여줍니다. **아직 빵이 준비가 안 됐네요.**는 대화만 닫고 손님은 기다립니다. **오늘 그 빵은 더 못 팔아요.**는 손님을 돌려보냅니다. 폐점하면 대기 주문이 취소됩니다. 메뉴/대화 중 손님 도착 시간과 게임 시계는 멈추지만, 이미 시작한 굽기는 진행됩니다. 노크음은 음악 설정의 음량·음소거를 따릅니다. 소리가 막힌 환경에서도 화면에 노크 안내가 나옵니다.

반죽·토핑·굽기 단계는 닫아도 유지됩니다. **ESC → 저장**하면 진행도와 오븐의 남은 시간도 파일에 보관됩니다. 게임을 종료한 동안 자동으로 굽거나 자라지는 않습니다. 반죽이 진행 중이면 두 번째 반죽을 동시에 만들 수 없습니다.

### 잡화점의 개별 판매
사거리 오른쪽 길 → 소도시 오른쪽 위 잡화점 → **잡화점 직원과 대화** → **상점을 둘러본다.**에서 하나씩 구매합니다. 대화를 닫으면 다시 직원에게 말을 걸어야 구매 창을 열 수 있습니다.

| 상품 | 1개 가격 |
| --- | ---: |
| 밀가루 | 2G |
| 이스트 | 3G |
| 소금 | 1G |
| 꿀 | 5G |
| 베리 씨앗 | 8G |

미라의 부탁은 창고에서 꺼낸 밀빵을 가방에 보관한 채 전달하세요. 사거리 동쪽 길가의 야생 베리는 한 번에 6개로 늘렸고, 게임 시간 30분 뒤 다시 수확할 수 있습니다.

### 서쪽 베리 텃밭
사거리에서 소도시와 **반대 방향인 왼쪽 길 끝**으로 걸으면 베리 텃밭으로 이동합니다. 오른쪽 길 끝으로 돌아옵니다.

- 밭은 6개입니다. 각 밭 아래로 접근해 E를 누르면 관리 창이 열립니다.
- 잡화점에서 산 **베리 씨앗 1개**로 심고 **물 주기**를 누릅니다. 물 주기에는 별도 소모품이 필요 없습니다.
- 물을 준 뒤 **게임 시간 2시간**이 지나면 베리 8개를 수확합니다. 평소 속도로 약 1분이며, ESC 메뉴의 다음 날 아침으로 넘겨도 됩니다.
- 수확 후 밭은 비어 새 씨앗을 심을 수 있습니다. 씨앗·물주기·성장 상태도 저장됩니다.

### 우체국과 소도시
- 사거리 오른쪽 위 건물은 **달빛 우체국**입니다. 문으로 들어가 **우체국 직원과 대화** → **네, 서명할게요.** → 답변을 끝까지 넘기면 소포 수령. 하루 한 번 밀가루 4, 꿀 1을 받습니다.
- 사거리의 오른쪽 길 끝을 걸어가면 **해봄 소도시**입니다. 첨부 이미지에 맞춰 카페·잡화점·마을 회관·공방이 있고, 대화 가능한 주민 3명이 있습니다. 잡화점은 재료 구매가 가능하며 나머지 건물 내부는 준비 중입니다. 왼쪽 길로 돌아옵니다.
- 기존 주민 세 명과 퀘스트 세 개도 유지됩니다.

## 실내 화면과 기존 세이브
빵집·우체국·잡화점에 들어가면 1인칭 정면 화면이 표시되며 캐릭터 이동은 멈춥니다. 화면 위 물건별 버튼으로 기능을 이용하고, 오른쪽 아래 **광장으로 나가기**로 원래 건물 앞에 돌아옵니다. 판매실/작업실/잡화점에서도 저장할 수 있습니다. 기존 실내 세이브도 불러올 수 있으며, 배경 변경으로 건물 안에 겹친 기존 실외 위치는 안전한 길로 옮깁니다. 소지품·돈·퀘스트는 보존합니다. 저장 포맷은 버전 4입니다. 버전 1/2/3 파일을 불러오면 돈·물품·퀘스트·창고·기존 주문을 보존하고 자동 이관합니다. 새 재료가 없던 세이브에는 이스트 6개·소금 6개·베리 씨앗 2개를 초기 지급합니다. 이후 최신 버전으로 저장하면 다시 지급하지 않습니다. 버전 3에서 옮길 때에는 재료를 재지급하지 않고 반죽·농사·재고를 유지한 채 우체국 방문 기록만 추가합니다. 업데이트 전 saves 폴더를 백업해 두세요.

## 플레이어 이미지와 애니메이션
업로드한 ZIP의 **원본 이미지 두 장을 배포본에 포함**했습니다. 메뉴에서 이미지를 다시 선택할 필요가 없습니다.

- `assets/characters/source/sheet-2.png`: 여러 포즈가 들어 있는 원본. 앞/뒤/오른쪽 대기 자세를 사용하고 왼쪽은 오른쪽의 좌우 반전으로 표시합니다.
- `assets/characters/source/sheet-1.png`: 별도 걷기 원본. 앞/뒤/오른쪽의 핵심 자세 세 장을 골라 내딛기→교차→반대발 내딛기→교차의 4단계 루프(0.4초)로 사용합니다. 상하 이동에는 각각 앞/뒤 걷기가 재생되며, 왼쪽은 오른쪽 루프를 그대로 미러링합니다.
- `player-idle.png`, `player-walk.png`: 캐릭터별 실루엣을 분리한 실행용 아틀라스입니다. 이웃 프레임의 꼬리가 섞이지 않도록 분리하고 머리 중심을 정렬했습니다. 걷기의 붉은 색조를 대기 팔레트에 맞추고 방향별 머리 너비와 몸 높이를 맞춰 정지/이동 간 크기 변화를 줄였습니다.
- `data/playerAnimations.json`: 방향별 프레임·정렬 기준점·재생 속도. 걷기를 멈추면 마지막 방향의 대기 포즈로 바뀝니다.
- 점프는 사용하지 않습니다. 빵 포즈가 있는 원본 넷째 줄은 `reservedBread`로 보관하며, 현재 플레이 중에는 재생하지 않습니다.

원본 파일은 수정하지 않고 보존합니다. `tools/build-player.py`는 실행용 아틀라스를 다시 만드는 개발 도구입니다(Python/Pillow 필요). 이미 생성된 이미지가 포함되어 있으므로 일반 게임 실행에는 Python이나 추가 설치가 필요 없습니다.

ESC 메뉴의 **플레이어 이미지 불러오기**는 선택 기능으로 남겨 두었습니다. 기존 1536×1024 다중 포즈 시트 형식을 위한 기능이며, 별도의 걷기 시트를 단독으로 불러오는 기능은 아닙니다. **기본 캐릭터로 복원**을 누르면 이번 ZIP의 원본 기반 4방향 애니메이션으로 돌아옵니다. 과거 버전의 임시 사용자 이미지가 새 기본 캐릭터를 가리지 않도록 예전 자동 선택 설정은 승계하지 않습니다. 새 버전에서 직접 선택한 사용자 이미지는 `saves/player-sheet.png`에 보관됩니다.

## 개발 구조
- main: 입력/루프, player: 충돌, sceneManager/exploration: 장소/상호작용
- renderer: 실외 픽셀 배경 및 맵 표시, playerSprite/playerAnimations: 기본 플레이어 이미지·방향별 프레임 (playerAtlas는 사용자 시트 호환용)
- interior/interiorArt: 클릭 기능·실내 정면 화면 (이동/저장과 분리)
- title/saveSystem/server: 타이틀/검증/파일 저장 API (3슬롯, 임시 파일 후 교체)
- shop/counterArt/effects: 창고·손님·소포·상반신 표시·노크음
- baking/bakingUI: 단계별 제빵·마우스 반죽·오븐
- bakery/inventory: 진열·개별 구매·물품
- garden/gardenArt: 서쪽 텃밭·심기·물주기·성장·수확
- dialogue/npc/quest/ui: 마을 대화/주민/퀘스트/패널
- serviceDialogue/serviceDialogues: 손님 주문 말투·세 가지 응답·직원 대화와 서비스 진입 조건
- staffArt: 직원 임시 일러스트 표시 (경로는 serviceDialogues.json의 portraitAsset)
- data: NPC/대사/퀘스트/레시피/소도시 JSON, assets: 캐릭터·빵 일러스트·배경·음원

`npm test`로 기존/새 시스템 테스트를 실행합니다. `node --check src/파일.js`로 구문 검사합니다. 외부 라이브러리는 필요 없습니다. 수정 후 브라우저를 새로고침하면 반영됩니다. 맵 960×576 논리 해상도를 비율 유지하여 확대하며, 색상·타일·장식 밀도를 높였습니다. 주요 장소는 사용자가 제공한 이미지 원본을 사용하고, 서쪽 텃밭은 첨부 구도를 참고해 새로 만든 빈 텃밭 배경에 상태별 작물 스프라이트를 덧그립니다.

GitHub에는 코드만 올리고 개인 `saves/*.json`은 제외합니다. 작업 규칙은 AGENTS.md를 따릅니다.

## 이번 버전 검증
- 시스템 테스트 42개 통과: 기존 제작/퀘스트/저장/이동, 창고/주문/소포, 실내 출구, 방향별 시트 프레임.
- Chromium에서 정면 실내 제작→창고→진열, 실내 이동 비활성화, 저장/불러오기, 광장 복귀, 우체국 수령 및 좁은 화면 클릭 검증.
- 첨부 원본 PNG의 프레임 분리와 투명 배경을 확인하고, Chromium에서 4방향 걷기/정지 포즈·기본 이미지 로딩을 검증했습니다. Windows 직접 실행은 미검증입니다.

### 걷기 보정 패치
- 원본 걷기 프레임 중 각 방향 3장만 사용하고 교차 자세를 반복하여 4단계 루프로 재생합니다. 한 주기는 0.4초입니다.
- 걸을 때만 확대되던 공통 배율을 제거했습니다. 방향별 대기 자세의 머리 너비/몸 높이에 맞춰 표시합니다.
- 프레임 정렬은 꼬리나 벌어진 발 대신 머리 중심을 사용하여, 위로 걸을 때 옆으로 튀던 표시를 보정했습니다.
- 방향별 대기 팔레트에 맞춰 걷기 이미지의 붉은 색조/명암을 보정합니다. 사용자 원본 PNG와 빵 포즈는 그대로 보존합니다.
- Chromium 픽셀 검사에서 모든 걷기 프레임의 표시 높이와 대기 자세 차이가 2픽셀 이내, 프레임 간 머리 중심 흔들림이 2픽셀 이내, 평균 RGB 차이가 채널당 3 이내임을 확인했습니다.

개발용 브라우저 회귀 검사는 `tools/check-player-browser.mjs`입니다. Playwright와 Chromium이 있는 환경에서 게임 서버를 실행한 뒤 실행하세요. 선택적으로 `BAKERY_BROWSER`에 Chromium 실행 파일 경로, `BAKERY_PLAYWRIGHT_MODULE`에 별도 설치한 Playwright 모듈 URL을 지정할 수 있습니다. 일반 게임 실행에는 필요 없습니다. 이 검사는 세이브 파일을 생성하거나 변경하지 않습니다.

### 첨부 배경 적용과 공간 분리 패치

- 좌우 걷기와 대기 화면이 실제로 동일한 픽셀의 미러링인지 브라우저 회귀 검사에 추가했습니다.

- 두 MP3의 전체 디코딩과 Chromium의 실제 재생 시간 진행, 장소 전환, 방 간 연속 재생, 곡 끝 반복, 음량/음소거 저장을 확인했습니다. Windows에서 직접 청취하는 검증은 수행하지 않았습니다.

손님은 진열장과 앞쪽 계산대 사이에 서며, 원본 이미지의 앞쪽 계산대 레이어를 손님보다 나중에 그려 하반신을 가립니다. 주문 안내는 얼굴 위에 표시합니다. 위치와 가림 경계는 src/counterArt.js의 counterLayout에서 조정합니다.

### 제공된 우체국·잡화점 이미지와 TXT 대화
- 실내 배경: assets/backgrounds/services/post-office.png / general-store.png. 배경 안에 그려진 직원을 그대로 사용하며 직원을 중복으로 덧그리지 않습니다.
- 대화 일러스트: assets/characters/clerks/post-clerk.png / cat-sisters.png. 우체국은 기존 이름 하나를 유지하고, 이름이 없는 두 자매는 첫째·둘째, 셋째는 TXT에 나온 에리나로 표시합니다.
- 원본 TXT는 data/source에 보존하고 대사·선택지·이동은 data/staffStories.json에 옮겼습니다. 소포 서명, 재방문 잡담, 칭찬, 누나의 편지, 세 자매 가족 이야기, 서로 구별하기, 에리나의 모든 분기와 원래 선택지로 돌아가기를 구현했습니다.
- TXT의 ‘한번에 출력’은 세 자매의 대사를 한 페이지에서 연속 출력하고, ‘끊어서 출력’은 각 대사/지문을 별도 페이지로 넘기도록 해석했습니다. 지문은 기울임꼴로 표시합니다.
- 우체국의 그날 첫 대화와 재방문을 구분합니다. 거절하거나 중간에 닫아도 미수령 소포를 잃지 않도록 재방문 메뉴에 서명 선택지를 추가했습니다. 소포는 서명 후 답변을 끝까지 넘겼을 때 하루 한 번만 지급합니다.
- TXT의 퇴장 선택지는 대화를 닫는 데 그치지 않고 실제 건물 밖으로 이동합니다. 중간 ESC/닫기는 아직 선택하지 않은 거래나 서명 지급을 자동 실행하지 않고 대화만 취소합니다. 이미 완료한 구매·판매는 유지됩니다.
- 글자 출력·줄 진행은 dialogueSequence.js, 표시/키 입력은 dialogueView.js, 직원 분기는 staffStory.js로 분리했습니다. 마을 주민과 빵집 손님도 같은 글자 출력 기능을 사용합니다.
- tests/staffStory.test.js는 TXT의 모든 인용 대사가 포함됐는지, 분기와 서명 지급 시점, 저장 이관 및 글자 단위 진행을 검사합니다. tools/check-service-browser.mjs는 실제 스페이스 입력, 출력 중 닫기, 전체 분기, 거래, 마을 퀘스트와 작은 화면을 검증합니다.

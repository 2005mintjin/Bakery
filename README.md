# 작은 화덕 · 달빛마을
빵집과 주민 이야기를 중심으로 하는 HTML5 픽셀 어드벤처입니다. 기존 런앤건 프로젝트와 독립적입니다.

## Windows 실행
1. 최초 한 번 Node.js LTS (20 이상)를 설치합니다.
2. 다운로드한 ZIP **전체를 압축 해제**합니다.
3. `launch.bat` 또는 `게임 실행.bat`을 더블클릭합니다. 준비 후 브라우저가 열립니다.
4. 종료할 때 서버 창에서 Ctrl+C를 누릅니다.

패키지 설치 없이 실행되며, `npm start`도 동일합니다. `index.html` 직접 열기는 지원하지 않습니다. 서버는 본인 PC의 127.0.0.1:5173에만 바인딩합니다. 구버전 서버 창이 열려 있으면 닫고 최신 폴더에서 다시 실행하세요. 배치 파일은 ASCII/CRLF이며 Node를 게임 폴더의 절대 경로로 호출합니다.

## 시작·저장
- 타이틀에서 세이브 1~3번 선택. 빈 슬롯을 고르면 파일을 만든 뒤 짧은 인트로가 나옵니다.
- **ESC → 저장**으로 게임 폴더의 `saves/slot-N.json`에 저장합니다. 자동 저장은 없습니다.
- 같은 폴더의 세이브는 브라우저를 바꿔도 불러옵니다. 다운로드한 새 버전으로 옮길 때 기존 `saves` 폴더를 복사하세요.
- 구버전 localStorage 저장은 타이틀의 이전 저장 옮기기로 빈 슬롯에 가져옵니다. 이전과 같은 브라우저/주소에서 실행해야 합니다.
- 타이틀로 돌아가면 저장하지 않은 진행을 잃습니다. 손상된 파일은 자동으로 덮어쓰지 않습니다. 백업을 복원하세요.
- 파일 저장은 Node 서버 API가 필요하므로 GitHub Pages 같은 정적 호스팅은 지원하지 않습니다.

## 조작과 플레이
실외에서는 WASD/방향키 이동, E 상호작용. 실내에서는 정면 1인칭 화면의 버튼을 클릭합니다. I 가방, J 부탁 수첩, ESC 메뉴는 공통입니다. 대화는 클릭 또는 Tab/Enter. 메뉴/대화 중 시간과 손님 도착이 멈춥니다.

### 빵집 운영
1. 사거리 왼쪽 위 작은 화덕 문으로 들어갑니다.
2. **화덕 · 빵 굽기**를 클릭합니다. 완성한 빵은 **창고**에 보관됩니다.
3. **빵 창고** 클릭 → 원하는 빵 꺼내기. 가방에 들어갑니다.
4. **진열대 · 손님 응대** 클릭 → 빵 진열.
5. **영업 안내판** 클릭 → 개점.
6. 메뉴를 닫고 플레이 시간 12초가 지나면 손님이 도착합니다. 진열대에서 주문을 보고 요청한 빵을 건네면 한 개가 판매됩니다.
7. 요청한 빵이 없으면 준비한 뒤 응대하거나 주문을 거절할 수 있습니다. 한 번에 한 손님이 기다리며 다음 손님은 응대 후 12초 뒤 도착합니다. 폐점하면 대기 주문은 취소됩니다.

오른쪽 위 재료 상자에서 10G에 밀가루 4, 꿀 1을 구매합니다. 베리는 사거리 동쪽 덤불에서 E로 수확합니다. 미라의 밀빵 부탁은 창고에서 꺼낸 빵을 가방에 보관한 채 전달하세요.

### 우체국과 소도시
- 사거리 오른쪽 위 건물은 **달빛 우체국**입니다. 문으로 들어가 **소포 수령 창구** 클릭 → 소포 받기. 하루 한 번 밀가루 4, 꿀 1을 받습니다.
- 사거리의 오른쪽 길 끝을 걸어가면 **해봄 소도시**입니다. 건물 5개와 대화 가능한 주민 3명이 있습니다. 건물은 외관/충돌만 구현했으며 내부 콘텐츠는 준비 중입니다. 왼쪽 길로 돌아옵니다.
- 기존 주민 세 명과 퀘스트 세 개도 유지됩니다.

## 실내 화면과 기존 세이브
빵집·우체국에 들어가면 1인칭 정면 화면이 표시되며 캐릭터 이동은 멈춥니다. 화면 위 물건별 버튼으로 기능을 이용하고, 오른쪽 아래 **광장으로 나가기**로 원래 건물 앞에 돌아옵니다. 실내에서 저장한 구버전 세이브도 같은 장소의 정면 화면으로 불러옵니다. 저장 포맷은 버전 2를 유지하므로 기존 파일을 변환할 필요가 없습니다.

## 플레이어 이미지와 애니메이션
첨부 미리보기를 원본 파일로 가져올 수 없어 배포본에는 임시 `player.svg`가 남아 있습니다. 원본 PNG를 준비한 뒤 **ESC → 플레이어 이미지 불러오기**에서 선택하면 적용됩니다. 새 이미지 전체는 `saves/player-sheet.png`에 실제 파일로 보관되므로 다음 실행에도 사용되며, 후속 버전으로 옮길 때 saves 폴더 전체를 복사하세요. PNG 원본의 배경도 그대로 표시됩니다. 배경 제거 작업은 하지 않습니다.

`data/playerAtlas.json`에서 첨부 시트(1536×1024 미리보기 기준)의 영역을 관리합니다.
- 첫 줄: 아래/위/왼쪽/오른쪽으로 방향 전환한 후 서 있는 포즈를 선택합니다.
- 둘째 줄: 9프레임 걷기, 왼쪽 이동 시 좌우 반전. 제공된 줄에는 옆모습 걷기만 있어 위/아래 이동에도 같은 걷기 줄을 사용합니다. 상하 전용 걸음은 별도 원본이 필요합니다.
- 셋째 줄: 점프 미사용.
- 넷째 줄: 빵 포즈 10칸의 영역을 `reservedBread`로 예약합니다. 원본 전체가 파일로 보존되므로 향후 잘라 쓸 수 있습니다. 현재는 재생하지 않습니다.

원본이 미리보기와 다른 배치라면 JSON의 영역만 조정하세요. 시트 분리 로직은 `src/playerSprite.js`이며 실내 화면과 분리되어 있습니다. 실제 첨부 이미지가 없으므로 프레임 경계는 미리보기 기준 추정값입니다. 실제 원본 시트 적용은 아직 미검증입니다. 과거 브라우저에 저장한 이미지가 있다면 새 원본을 선택해 교체하세요.

## 개발 구조
- main: 입력/루프, player: 충돌, sceneManager/exploration: 장소/상호작용
- renderer: 실외 픽셀 배경 및 맵 표시, playerSprite/playerAtlas: 플레이어 이미지·프레임
- interior/interiorArt: 클릭 기능·실내 정면 화면 (이동/저장과 분리)
- title/saveSystem/server: 타이틀/검증/파일 저장 API (3슬롯, 임시 파일 후 교체)
- shop: 창고/손님/소포, bakery/inventory: 제작/진열/재료
- dialogue/npc/quest/ui: 대화/주민/퀘스트/패널
- data: NPC/대사/퀘스트/레시피/소도시 JSON, assets: 이미지 및 추후 음원

`npm test`로 기존/새 시스템 테스트를 실행합니다. `node --check src/파일.js`로 구문 검사합니다. 외부 라이브러리는 필요 없습니다. 수정 후 브라우저를 새로고침하면 반영됩니다. 맵 960×576 논리 해상도를 비율 유지하여 확대하며, 색상·타일·장식 밀도를 높였습니다. 배경은 외부 게임 자산을 사용하지 않는 자체 픽셀 드로잉입니다.

GitHub에는 코드만 올리고 개인 `saves/*.json`은 제외합니다. 작업 규칙은 AGENTS.md를 따릅니다.

## 이번 버전 검증
- 시스템 테스트 10개 통과: 기존 제작/퀘스트/저장/이동, 창고/주문/소포, 실내 출구, 방향별 시트 프레임.
- Chromium에서 정면 실내 제작→창고→진열, 실내 이동 비활성화, 저장/불러오기, 광장 복귀, 우체국 수령 및 좁은 화면 클릭 검증.
- 합성 PNG로 원본 전체 파일 저장/불러오기 확인. 실제 첨부 원본의 시각 품질과 프레임 경계, Windows 직접 실행은 미검증.

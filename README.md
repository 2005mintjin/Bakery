# 작은 화덕 · 달빛마을
빵집과 주민 이야기를 중심으로 하는 HTML5 픽셀 어드벤처입니다. 기존 런앤건 프로젝트와 독립적입니다.

## Windows 실행
1. 최초 한 번 Node.js LTS (20 이상)를 설치합니다.
2. 다운로드한 ZIP **전체를 압축 해제**합니다.
3. `launch.bat` 또는 `게임 실행.bat`을 더블클릭합니다. 준비 후 브라우저가 열립니다.
4. 종료할 때 서버 창에서 Ctrl+C를 누릅니다.

패키지 설치 없이 실행되며, `npm start`도 동일합니다. `index.html` 직접 열기는 지원하지 않습니다. 서버는 본인 PC의 127.0.0.1:5173에만 바인딩합니다. 구버전 서버 창이 열려 있으면 닫고 최신 폴더에서 다시 실행하세요. 배치 파일은 ASCII/CRLF이며 Node를 게임 폴더의 절대 경로로 호출합니다.

## 시작·저장
- 타이틀에서 세이브 1~3번 선택. 빈 슬롯을 고르면 파일을 만든 뒤 짧은 인트로가 나옵니다.
- **ESC → 저장**으로 게임 폴더의 `saves/slot-N.json`에 저장합니다. 자동 저장은 없습니다.
- 같은 폴더의 세이브는 브라우저를 바꿔도 불러옵니다. 다운로드한 새 버전으로 옮길 때 기존 `saves` 폴더를 복사하세요.
- 구버전 localStorage 저장은 타이틀의 이전 저장 옮기기로 빈 슬롯에 가져옵니다. 이전과 같은 브라우저/주소에서 실행해야 합니다.
- 타이틀로 돌아가면 저장하지 않은 진행을 잃습니다. 손상된 파일은 자동으로 덮어쓰지 않습니다. 백업을 복원하세요.
- 파일 저장은 Node 서버 API가 필요하므로 GitHub Pages 같은 정적 호스팅은 지원하지 않습니다.

## 조작과 플레이
실외에서는 WASD/방향키 이동, E 상호작용. 실내에서는 정면 1인칭 화면의 버튼을 클릭합니다. I 가방, J 부탁 수첩, ESC 메뉴는 공통입니다. 대화는 클릭 또는 Tab/Enter. 메뉴/대화 중 시간과 손님 도착이 멈춥니다.

### 빵집 운영
1. 사거리 왼쪽 위 빵집 문 앞에서 E를 누르거나, 문 쪽으로 걸어 들어갑니다.
2. 판매실 오른쪽 **작업실 →** 화살표를 누릅니다. 작업실에 화덕과 빵 창고가 있습니다.
3. **화덕 · 빵 굽기** 클릭. 완성한 빵은 창고에 보관됩니다.
4. **빵 창고** 클릭 → 원하는 빵 꺼내기. 가방에 들어갑니다.
5. **← 판매실** 화살표로 돌아와 **진열대 · 손님 응대**에서 빵을 진열합니다.
6. **영업 안내판**에서 개점합니다. 메뉴를 닫고 플레이 시간 12초가 지나면 손님이 옵니다.
7. 진열대에서 주문한 빵을 건네면 한 개가 판매됩니다. 준비가 안 됐다면 나중에 응대하거나 거절하세요. 한 번에 한 손님이 기다리며 폐점 시 대기 주문은 취소됩니다.

**재료 구매는 소도시 잡화점으로 이동했습니다.** 사거리 오른쪽 길 → 소도시 오른쪽 위 잡화점 문 앞 E → 재료 주문. 10G에 밀가루 4, 꿀 1을 구매합니다. 빵집에서는 재료를 주문하지 않습니다. 베리는 사거리 동쪽 길가에서 E로 수확합니다. 미라의 부탁은 창고에서 꺼낸 밀빵을 가방에 보관한 채 전달하세요.

### 우체국과 소도시
- 사거리 오른쪽 위 건물은 **달빛 우체국**입니다. 문으로 들어가 **소포 수령 창구** 클릭 → 소포 받기. 하루 한 번 밀가루 4, 꿀 1을 받습니다.
- 사거리의 오른쪽 길 끝을 걸어가면 **해봄 소도시**입니다. 첨부 이미지에 맞춰 카페·잡화점·마을 회관·공방이 있고, 대화 가능한 주민 3명이 있습니다. 잡화점은 재료 구매가 가능하며 나머지 건물 내부는 준비 중입니다. 왼쪽 길로 돌아옵니다.
- 기존 주민 세 명과 퀘스트 세 개도 유지됩니다.

## 실내 화면과 기존 세이브
빵집·우체국·잡화점에 들어가면 1인칭 정면 화면이 표시되며 캐릭터 이동은 멈춥니다. 화면 위 물건별 버튼으로 기능을 이용하고, 오른쪽 아래 **광장으로 나가기**로 원래 건물 앞에 돌아옵니다. 판매실/작업실/잡화점에서도 저장할 수 있습니다. 기존 실내 세이브도 불러올 수 있으며, 배경 변경으로 건물 안에 겹친 기존 실외 위치는 안전한 길로 옮깁니다. 소지품·돈·퀘스트는 보존합니다. 저장 포맷은 버전 2를 유지하므로 기존 파일을 변환할 필요가 없습니다.

## 플레이어 이미지와 애니메이션
업로드한 ZIP의 **원본 이미지 두 장을 배포본에 포함**했습니다. 메뉴에서 이미지를 다시 선택할 필요가 없습니다.

- `assets/characters/source/sheet-2.png`: 여러 포즈가 들어 있는 원본. 앞/뒤/오른쪽 대기 자세를 사용하고 왼쪽은 오른쪽의 좌우 반전으로 표시합니다.
- `assets/characters/source/sheet-1.png`: 별도 걷기 원본. 앞/뒤/오른쪽의 핵심 자세 세 장을 골라 내딛기→교차→반대발 내딛기→교차의 4단계 루프(0.4초)로 사용합니다. 상하 이동에는 각각 앞/뒤 걷기가 재생되며, 왼쪽은 오른쪽 루프를 그대로 미러링합니다.
- `player-idle.png`, `player-walk.png`: 캐릭터별 실루엣을 분리한 실행용 아틀라스입니다. 이웃 프레임의 꼬리가 섞이지 않도록 분리하고 머리 중심을 정렬했습니다. 걷기의 붉은 색조를 대기 팔레트에 맞추고 방향별 머리 너비와 몸 높이를 맞춰 정지/이동 간 크기 변화를 줄였습니다.
- `data/playerAnimations.json`: 방향별 프레임·정렬 기준점·재생 속도. 걷기를 멈추면 마지막 방향의 대기 포즈로 바뀝니다.
- 점프는 사용하지 않습니다. 빵 포즈가 있는 원본 넷째 줄은 `reservedBread`로 보관하며, 현재 플레이 중에는 재생하지 않습니다.

원본 파일은 수정하지 않고 보존합니다. `tools/build-player.py`는 실행용 아틀라스를 다시 만드는 개발 도구입니다(Python/Pillow 필요). 이미 생성된 이미지가 포함되어 있으므로 일반 게임 실행에는 Python이나 추가 설치가 필요 없습니다.

ESC 메뉴의 **플레이어 이미지 불러오기**는 선택 기능으로 남겨 두었습니다. 기존 1536×1024 다중 포즈 시트 형식을 위한 기능이며, 별도의 걷기 시트를 단독으로 불러오는 기능은 아닙니다. **기본 캐릭터로 복원**을 누르면 이번 ZIP의 원본 기반 4방향 애니메이션으로 돌아옵니다. 과거 버전의 임시 사용자 이미지가 새 기본 캐릭터를 가리지 않도록 예전 자동 선택 설정은 승계하지 않습니다. 새 버전에서 직접 선택한 사용자 이미지는 `saves/player-sheet.png`에 보관됩니다.

## 개발 구조
- main: 입력/루프, player: 충돌, sceneManager/exploration: 장소/상호작용
- renderer: 실외 픽셀 배경 및 맵 표시, playerSprite/playerAnimations: 기본 플레이어 이미지·방향별 프레임 (playerAtlas는 사용자 시트 호환용)
- interior/interiorArt: 클릭 기능·실내 정면 화면 (이동/저장과 분리)
- title/saveSystem/server: 타이틀/검증/파일 저장 API (3슬롯, 임시 파일 후 교체)
- shop: 창고/손님/소포, bakery/inventory: 제작/진열/재료
- dialogue/npc/quest/ui: 대화/주민/퀘스트/패널
- data: NPC/대사/퀘스트/레시피/소도시 JSON, assets: 이미지 및 추후 음원

`npm test`로 기존/새 시스템 테스트를 실행합니다. `node --check src/파일.js`로 구문 검사합니다. 외부 라이브러리는 필요 없습니다. 수정 후 브라우저를 새로고침하면 반영됩니다. 맵 960×576 논리 해상도를 비율 유지하여 확대하며, 색상·타일·장식 밀도를 높였습니다. 배경은 외부 게임 자산을 사용하지 않는 자체 픽셀 드로잉입니다.

GitHub에는 코드만 올리고 개인 `saves/*.json`은 제외합니다. 작업 규칙은 AGENTS.md를 따릅니다.

## 이번 버전 검증
- 시스템 테스트 16개 통과: 기존 제작/퀘스트/저장/이동, 창고/주문/소포, 실내 출구, 방향별 시트 프레임.
- Chromium에서 정면 실내 제작→창고→진열, 실내 이동 비활성화, 저장/불러오기, 광장 복귀, 우체국 수령 및 좁은 화면 클릭 검증.
- 첨부 원본 PNG의 프레임 분리와 투명 배경을 확인하고, Chromium에서 4방향 걷기/정지 포즈·기본 이미지 로딩을 검증했습니다. Windows 직접 실행은 미검증입니다.

### 걷기 보정 패치
- 원본 걷기 프레임 중 각 방향 3장만 사용하고 교차 자세를 반복하여 4단계 루프로 재생합니다. 한 주기는 0.4초입니다.
- 걸을 때만 확대되던 공통 배율을 제거했습니다. 방향별 대기 자세의 머리 너비/몸 높이에 맞춰 표시합니다.
- 프레임 정렬은 꼬리나 벌어진 발 대신 머리 중심을 사용하여, 위로 걸을 때 옆으로 튀던 표시를 보정했습니다.
- 방향별 대기 팔레트에 맞춰 걷기 이미지의 붉은 색조/명암을 보정합니다. 사용자 원본 PNG와 빵 포즈는 그대로 보존합니다.
- Chromium 픽셀 검사에서 모든 걷기 프레임의 표시 높이와 대기 자세 차이가 2픽셀 이내, 프레임 간 머리 중심 흔들림이 2픽셀 이내, 평균 RGB 차이가 채널당 3 이내임을 확인했습니다.

개발용 브라우저 회귀 검사는 `tools/check-player-browser.mjs`입니다. Playwright와 Chromium이 있는 환경에서 게임 서버를 실행한 뒤 실행하세요. 선택적으로 `BAKERY_BROWSER`에 Chromium 실행 파일 경로, `BAKERY_PLAYWRIGHT_MODULE`에 별도 설치한 Playwright 모듈 URL을 지정할 수 있습니다. 일반 게임 실행에는 필요 없습니다. 이 검사는 세이브 파일을 생성하거나 변경하지 않습니다.

### 첨부 배경 적용과 공간 분리 패치
- `assets/backgrounds/reference/reference-2.png`: 빵집·우체국 사거리 원본을 배경 레이어로 직접 사용합니다.
- `reference-1.png`: 카페·잡화점·회관·공방 소도시 원본을 사용합니다. 원본 비율을 유지해 화면을 채우므로 위아래 가장자리는 조금 잘립니다.
- 게임 좌표는 960×576을 유지하고, 캔버스와 배경 캐시는 1920×1152로 그려 이미지의 세부 픽셀을 보존합니다. 버튼은 비율 기반 DOM 배치로 크기가 바뀌어도 클릭 위치가 유지됩니다.
- `data/worldMaps.json`: 건물 충돌·출입구·구버전 세이브 안전 위치. 이미지 파일과 분리해 조정합니다.
- `src/roomArt.js`: 판매실/작업실/잡화점의 정면 픽셀 그래픽.
- 좌우 걷기와 대기 화면이 실제로 동일한 픽셀의 미러링인지 브라우저 회귀 검사에 추가했습니다.
- Chromium에서 문으로 진입 → 작업실 이동 → 제작/창고 → 판매실 진열 → 잡화점 입장/구매 → 저장/불러오기와 좁은 화면 클릭을 확인했습니다.

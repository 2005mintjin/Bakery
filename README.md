# 펜서 베이커리 · 달빛마을
빵집과 주민 이야기를 중심으로 하는 HTML5 픽셀 어드벤처입니다. 기존 런앤건 프로젝트와 독립적입니다.

## 새 이름과 접속 주소

게임 이름은 **펜서 베이커리 (Fencer Bakery)**입니다.

**https://2005mintjin.github.io/Bakery/fencer-bakery/**

예전 `/Bakery/` 주소도 새 주소로 자동 연결됩니다. GitHub 저장소는 Bakery라는 이름을 유지하며, 새 게임 진입점만 추가했습니다. 브라우저 탭·웹 헤더·게임 타이틀·빵집/작업실 메뉴·다운로드 세이브 이름에 새 이름을 사용합니다.

기존 웹 세이브는 `/Bakery/` 저장 키를 계속 사용하여 그대로 읽고 씁니다. 주소가 바뀌어도 초기화하거나 복사하지 않으며, 세이브 삭제 기능은 같은 슬롯을 대상으로 동작합니다. 내부 little-hearth 저장 ID는 호환성을 위해 유지합니다.

## 현재 정식 웹 버전

검토된 데모 변경을 정식 사이트 **https://2005mintjin.github.io/Bakery/fencer-bakery/** 에 반영합니다. 세이브 삭제, 플레이어 이미지 교체/복원 제거, 큰 글자, 우체국 직원 료, 공방 소마·크레마토리의 이미지·대사·직원별 구매·빵집 방문·글자별 목소리를 포함합니다.

기존 정식 웹 세이브 키 `little-hearth:web:/Bakery/`와 저장 버전 8을 유지합니다. 데모의 별도 세이브를 정식 저장에 덮어쓰지 않습니다. 기존 정식 PC 실행도 5173·saves 폴더를 유지합니다. 데모를 이어서 플레이하려면 정식 사이트의 **세이브 파일 가져오기**로 데모에서 내보낸 JSON을 선택하세요.

정식 모드 검사: 테스트 113개 통과, 데모 배포 차단 전용 검사 1개는 정식 모드에서 제외합니다. 정적 /Bakery/ 환경의 기존 저장 인식·저장/삭제·JSON 이동·새 직원 대화/구매/방문객·세 MP3 디코딩 및 글자별 재생을 검증합니다. Windows 직접 실행·청취는 미확인입니다.

## 료·소마·크레마토리 목소리 (정식 반영)

`Downloads (11).zip`의 MP3 3개를 파일명에 맞춰 적용했습니다. 료는 우체국 대화와 빵집 방문에, 소마·크레마토리는 공방 대화와 빵집 방문에 각각 같은 목소리를 사용합니다. 원본 MP3는 변경하지 않았습니다.

기존 글자별 재생 방식을 유지하며, 말줄임표·공백·구두점·나레이션은 무음입니다. 스페이스로 남은 글자를 한 번에 표시할 때 소리가 몰아 재생되지 않으며, 대화 종료·페이지 전환·음소거 시 중단합니다. 공통 음량 설정도 적용됩니다. 매핑은 `data/voices.json`, 파일은 `assets/audio/voices/ryo.mp3`, `soma.mp3`, `crematory.mp3`입니다.

테스트 113개와 실제 Chromium MP3 디코딩·글자별 재생·새 직원/방문객 매핑·무음·건너뛰기·ESC·음소거 검사를 통과했습니다. 정식 사이트에도 반영했으며 Windows 직접 청취는 미확인입니다.

## 료·소마·크레마토리 추가 패치 (정식 반영)

- 우체국 직원 **하나를 료로 교체**했습니다. 첨부 우체국 배경·상반신·SD를 사용하고 새 TXT의 첫 방문·소포 서명·재방문·잡담·누나의 편지 대사를 반영했습니다. 하루 한 번 소포 수령은 유지합니다. 수령 전 대화를 끊어도 재방문 후 서명할 수 있습니다.
- 공방 배경을 첨부 원본으로 교체했습니다. **왼쪽 소마**와 대화해 **제빵용 틀이 필요해서요.**를 선택하면 파이 틀·쿠키 틀만 판매합니다. **오른쪽 크레마토리(크레마)**와 대화해 **저희 빵집 오븐을 손봐주셨으면 해요.**를 선택하면 오븐 개량만 표시합니다. 구매 화면을 닫으면 다시 해당 직원과 대화합니다.
- 소마의 이시도로·약혼·곰의 포옹·옷차림 분기, 크레마토리의 카페·옷차림 분기를 TXT대로 한 줄씩 표시하며 선택지로 돌아갑니다. 스페이스 또는 다음으로 진행합니다.
- 료·소마·크레마토리 모두 빵집 손님으로 방문합니다. 카운터에서는 새 SD, 대화창에서는 별도 상반신을 사용하며, 첨부 대사의 말투에 맞춘 주문·감사·대기·거절 대사를 적용했습니다. 전체 방문객은 10명입니다.
- 기존 저장의 우체국 대기 주문은 제품·수량을 보존하고 료의 이름/그림으로 이어집니다. 저장 버전 8, 장비·개량 가격, 정식·데모 저장 분리를 유지합니다.

원본 PNG는 변형 없이 `assets/backgrounds/`와 `assets/characters/clerks/`, `visitors/`에 보관합니다. 대사 원본은 `data/source/post-dialogue.txt`, `mold-dialogue.txt`, `furnace-dialogue.txt`입니다. 새 세 사람의 목소리는 후속 `Downloads (11).zip`의 각 이름별 MP3로 적용했습니다.

검증: 전체 테스트 112개, 새 직원의 전 대사 원문·분기·구매 권한·저장 호환 검사와 임시 웹 호스트의 실제 대화/구매/새 방문객/카운터 가림/390px 화면 검사를 통과했습니다. Windows 직접 실행은 미확인입니다.

## 로컬 데모와 정식판

정식판은 `main`, 별도 검토용 데모는 `demo` 브랜치입니다. 두 버전 모두 ZIP을 새 폴더에 풀고 `게임 실행.bat`으로 실행합니다. Node.js 20 이상이 필요하며 추가 패키지는 없습니다. 이전 서버 창은 닫고 실행하세요.

- 정식 PC판: **http://127.0.0.1:5173**, **saves/**. 정식 웹은 기존 브라우저 저장 키를 사용합니다.
- 데모판: **http://127.0.0.1:5174**, **saves-demo/**. 별도 브라우저 저장 키와 DEMO 배지를 사용합니다.
- 두 버전 사이의 저장 이동은 **세이브 파일 가져오기/내보내기**로 직접 선택합니다. 자동으로 복사하거나 초기화하지 않습니다.
- 타이틀과 ESC 메뉴의 **세이브 삭제**는 슬롯 선택 후 확인해야 삭제합니다. 현재 슬롯을 삭제하면 타이틀로 이동하며 다른 슬롯·내보낸 백업은 보존합니다.
- 플레이어 이미지 불러오기·복원·자동 재적용은 제거했습니다. 기본 애니메이션만 사용하며 개인 이미지 파일을 임의로 지우지는 않습니다.
- 주요 본문·버튼은 16px, 대화는 20px, 작은 안내는 14px 중심으로 확대했습니다. 스타일은 `src/styles/readability.css`에서 수정합니다.

새 변경은 데모에서 확인하고 사용자가 정식 반영을 요청했을 때 승격합니다. `demoEdition`이 참인 데모에서는 `npm run publish:web`이 차단됩니다. 정식판에서는 검증 후 배포할 수 있습니다.

## 웹에서 바로 플레이

웹 배포 주소: **https://2005mintjin.github.io/Bakery/fencer-bakery/** (GitHub Pages 활성화 후 사용).
PC의 Chrome·Edge 등에서 링크를 열면 설치 없이 플레이합니다. WASD/방향키·E·마우스를 사용하므로 PC 브라우저를 권장합니다. 최초 접속에는 이미지와 음악을 불러오는 시간이 걸립니다.

웹 버전은 각자의 **브라우저 저장소에 슬롯 3개**를 저장합니다. 다른 사람의 세이브와 공유되지 않으며, 브라우저 데이터 삭제·다른 브라우저·다른 기기에서는 이어지지 않습니다. ESC → **세이브 파일 내보내기**로 백업하세요. PC 버전은 이전처럼 `saves/slot-N.json`에 저장합니다.

- 기존 PC 세이브를 웹으로: 사이트 타이틀의 **세이브 파일 가져오기** → PC `saves` 폴더의 JSON 선택 → 저장할 슬롯 선택.
- 웹 세이브를 PC로: ESC → **세이브 파일 내보내기** → PC 게임의 타이틀 또는 ESC 메뉴에서 **세이브 파일 가져오기**.
- 기존 슬롯에 가져올 때는 덮어쓰기 확인을 표시합니다. 저장 형식은 버전 8이고 구버전 파일도 자동 이관합니다.
- 현재 버전에서는 개인 캐릭터 이미지 교체를 지원하지 않으며 기본 캐릭터만 사용합니다.

### GitHub Pages 최초 설정

배포 파일은 `gh-pages` 브랜치에 있습니다. 사이트가 아직 열리지 않으면 저장소 **Settings → Pages → Build and deployment**에서 **Source: Deploy from a branch**, **Branch: gh-pages / (root)**를 선택하고 Save를 누르세요. GitHub의 배포가 끝나면 위 주소에서 열립니다.

코드 패치 후 웹사이트도 갱신하려면 Git이 인증된 개발 환경에서 `npm run publish:web`을 실행합니다. 설치/번들링 패키지는 필요 없습니다. 도구가 `dist/web`을 생성하고 정적 파일만 `gh-pages`에 올립니다. `saves`·서버·테스트·개발 설정은 배포하지 않으며 현재 작업 브랜치와 Git 인덱스는 유지합니다. `npm run build:web`은 업로드 없이 배포 폴더만 만듭니다. 일반 Windows 플레이에는 이 명령들이 필요 없습니다.

검증: 전체 테스트 105개와 JavaScript 115개 구문 검사를 통과했습니다. 정적 `/Bakery/` 경로의 웹 저장·새로고침·JSON 이동·슬롯 덮어쓰기 확인·개인 캐릭터 저장·사용자별 격리와 기존 PC 파일 저장을 Chromium에서 확인했습니다. 실제 GitHub Pages 활성화/외부 접속은 저장소 설정과 네트워크 접근 권한에 따라 별도 확인이 필요합니다.

## 공방·도구·판매 메뉴 패치

- 궁서체를 제거했습니다. 설치되어 있으면 **휴먼편지체/휴먼매직체**를 사용하고, 없으면 **맑은 고딕 등 시스템 고딕체**로 표시합니다. 별도 폰트 설치나 인터넷 연결은 필요 없습니다.
- 새 게임은 빵만 만들 수 있습니다. **사거리 오른쪽 소도시 → 오른쪽 아래 공방**의 문으로 들어가 **소마와 대화 · 제빵용 틀** 또는 **크레마토리와 대화 · 오븐 개량**을 클릭하세요.

| 공방 상품 | 가격 | 효과 |
| --- | ---: | --- |
| 파이 틀 | 150G | 파이 3종 반죽·굽기 해금 |
| 쿠키 틀 | 120G | 쿠키 3종 반죽·굽기 해금 |
| 용량 확장 1 / 2단계 | 250 / 500G | 한 판 6 → 9 → 12개 |
| 화력 개선 1 / 2단계 | 200 / 400G | 굽기·건조 60 → 45 → 30초 |

도구는 한 번만 구입합니다. 용량·속도는 각각 개량하며, 오븐에 굽거나 건조한 제품이 있으면 꺼낸 뒤 개량할 수 있습니다. 작업실·창고·오븐의 수량과 타이머 표시도 개량을 반영합니다.

**영업 안내판**에서 판매할 제품을 체크하고 **판매 메뉴 적용** 또는 **개점하기**를 누르세요. 최소 한 종류를 선택해야 하며, 손님은 그 목록에서 선호도에 따라 무작위로 1~3개를 주문합니다. 도구 구매 후 파이·쿠키도 선택할 수 있습니다. 진열 수량은 따로 관리합니다. 영업 중 메뉴를 바꿔도 대기 손님의 주문은 보존하며 다음 손님부터 적용합니다.

카운터 손님 가림은 새 판매실 배경의 테이블 윗면에 맞췄습니다. 하반신이 테이블 앞에 그려지지 않습니다.

저장 형식은 **버전 8**입니다. 버전 1~7의 돈·물품·퀘스트·반죽·굽기 시간을 보존합니다. 이전 저장에 해당 파이/쿠키 완제품·진열·반죽·오븐 작업이 있거나 치대는 중이면 해당 틀을 보유한 것으로 이관하고, 오븐은 기본 6개·60초에서 시작합니다. 새 저장은 도구 구매·개량 단계·판매 메뉴·굽기 시간을 함께 저장합니다. 업데이트할 때 실행 중인 서버 창을 먼저 닫고, 새 폴더에 기존 `saves` 폴더를 복사한 뒤 새 `게임 실행.bat`을 실행하세요. 배치 파일과 설치 방법은 같습니다.

검증: 테스트 101개, 공방 실제 출입·도구 구매·잠금·개량·저장 복원·판매 메뉴 제한·8명 손님의 가림 픽셀 비교·작은 화면·기존 제작 UI 브라우저 검사를 통과했습니다. Windows 직접 실행은 이 Linux 환경에서 확인하지 못했습니다.

## 새 UI 사용법
웹페이지와 게임 메뉴를 짙은 목재·양피지·금빛 장식으로 통일했습니다. 화면 옆에는 날짜·시각·소지금·기력과 빠른 메뉴가 있고, 작은 화면에서는 아래로 배치됩니다.

- **작업대 · 레시피**: 빵 / 파이 / 쿠키 탭을 골라 해당 종류의 재료와 완성품만 봅니다. 재료 준비 → 반죽 → 토핑 → 보관 흐름을 단계 표시로 확인합니다.
- **오븐 관리**: 종류별 탭에서 수량을 입력합니다. 탭을 바꿔도 ‘이번 판’에 담은 수량은 유지되며, 모든 종류를 합쳐 최대 6개입니다. ‘선택 초기화’로 비울 수 있습니다.
- **반죽·빵 창고**: 종류별로 준비 반죽·구운 재고·가방 수량을 확인하고 꺼내거나 보관합니다.
- **가방**: 전체 / 재료 / 완성품 / 씨앗으로 나누고, 물건을 클릭하면 수량과 설명을 확인합니다.
- 종류 탭은 클릭 또는 좌우 방향키로 전환합니다. ESC로 창을 닫습니다.

설치·실행 방법은 그대로이며 현재 저장 형식은 버전 8입니다. 기존 `saves` 폴더를 유지해 업데이트할 수 있습니다. 추가 패키지 설치나 빌드는 필요 없습니다.

검증: 전체 테스트 95개·JavaScript 101개 구문 검사 통과. `tools/check-ui-browser.mjs`로 종류 탭·키보드 포커스·혼합 선택 유지·6개 제한·창고·가방·390px 반죽 입력을 확인했고, 기존 카페 대사·선택지·구매·저장 복원 검사도 통과했습니다. Windows 직접 실행은 이 Linux 환경에서 확인하지 못했습니다.

## Windows 실행
1. 최초 한 번 Node.js LTS (20 이상)를 설치합니다.
2. 다운로드한 ZIP **전체를 압축 해제**합니다.
3. `launch.bat` 또는 `게임 실행.bat`을 더블클릭합니다. 준비 후 브라우저가 열립니다.
4. 종료할 때 서버 창에서 Ctrl+C를 누릅니다.

패키지 설치 없이 실행되며, `npm start`도 동일합니다. `index.html` 직접 열기는 지원하지 않습니다. 서버는 본인 PC의 127.0.0.1:5173에만 바인딩합니다. 구버전 서버 창이 열려 있으면 닫고 최신 폴더에서 다시 실행하세요. 배치 파일은 ASCII/CRLF이며 Node를 게임 폴더의 절대 경로로 호출합니다.

## 시작·저장
- 타이틀에서 세이브 1~3번 선택. 빈 슬롯을 고르면 파일을 만든 뒤 짧은 인트로가 나옵니다.
- **ESC → 저장**으로 게임 폴더의 `saves/slot-N.json`에 저장합니다. 자동 저장은 없습니다.
- 같은 폴더의 세이브는 브라우저를 바꿔도 불러옵니다. 다운로드한 새 버전으로 옮길 때 기존 `saves` 폴더를 복사하세요.
- 구버전 localStorage 저장은 타이틀의 이전 저장 옮기기로 빈 슬롯에 가져옵니다. 이전과 같은 브라우저/주소에서 실행해야 합니다.
- 타이틀로 돌아가면 저장하지 않은 진행을 잃습니다. 손상된 파일은 자동으로 덮어쓰지 않습니다. 백업을 복원하세요.
- 파일 저장은 Node 서버 API가 필요하므로 GitHub Pages 같은 정적 호스팅은 지원하지 않습니다.

## 조작과 플레이
실외에서는 WASD/방향키 이동, E 상호작용. 실내에서는 정면 1인칭 화면의 버튼을 클릭합니다. I 가방, J 부탁 수첩, ESC 메뉴는 공통입니다. 대사는 한 글자씩 출력합니다. **스페이스 / 다음**은 출력 중인 줄을 완성하고, 다시 누르면 다음 줄로 넘어갑니다. 마지막 줄 다음에는 선택지가 나타나며 클릭 또는 Tab/Enter로 고릅니다. ESC/닫기로 중간 취소할 수 있습니다. 메뉴/대화 중 시간과 손님 도착이 멈춥니다.

### 빵집 운영과 제빵
1. 빵집 **작업실 → 작업대 · 반죽 만들기**에서 빵·파이·쿠키 반죽을 선택합니다. 빵은 기존 **재료 섞어 반죽 시작**, 파이와 쿠키는 각각의 반죽 시작 버튼을 사용합니다. 반죽 하나에 기력 10을 사용하며 종류별 재료는 아래 표를 확인하세요.
2. 반죽 위에서 **마우스를 누른 채 좌우로 문질러 100%**까지 치댑니다. 화면 크기가 달라도 좌표를 보정하며, 닫거나 저장해도 진행도가 유지됩니다.
3. 속재료 또는 토핑을 하나 고르면 준비된 반죽이 자동으로 창고에 쌓입니다. 빵은 **없음 → 밀빵 / 꿀 → 꿀빵 / 베리 → 베리빵**, 파이·쿠키는 아래 레시피에 따라 완성합니다. 바로 굽지 않고 다음 반죽을 계속 만들 수 있습니다.
4. **빵 창고**에서 종류별 준비 반죽·구운 빵·가방 수량과 오븐 수량을 확인합니다. 준비 반죽에는 보관 개수 제한이 없고, 치대는 반죽은 한 번에 하나입니다.
5. **오븐 · 최대 6개 굽기**에서 종류별 개수를 정한 뒤 **선택한 반죽 굽기**를 누릅니다. 서로 다른 종류를 섞어 **합계 1~6개**를 한 판으로 굽습니다. 기본 입력은 준비 반죽에서 최대 6개를 담습니다. 0개·7개 이상·준비 수량 초과는 시작할 수 없습니다.
6. 한 판을 굽는 데 **실제 플레이 시간 60초**가 걸립니다. 굽는 동안 다른 반죽을 만들거나 메뉴·다른 장소를 이용할 수 있습니다. 다른 탭에서는 굽기가 멈춥니다. 이미 굽기 시작한 판에는 반죽을 추가하지 않습니다.
7. 완료 후 **완성한 빵 모두 꺼내기**로 구운 빵을 창고에 옮깁니다. 꺼내기 전에는 다음 판을 굽지 못합니다. 준비 반죽과 굽는 중인 판, 치대는 반죽은 각각 독립적으로 저장됩니다.
8. 창고에서 구운 빵을 꺼내 판매실 진열대에 올리고 **영업 안내판 → 개점**으로 손님을 받습니다. 진열장은 첨부된 가득 찬 배경 그대로이며, 실제 판매 수량은 화면 아래 재고 패널에서 확인합니다.

한 번에 손님 한 명이 기다립니다. 플레이 시간 12초마다 노크 후 손님이 계산대 뒤에 나타납니다. 손님은 각자 제품과 1~3개 수량을 무작위로 주문합니다. **손님과 대화하기**에서 **네, 금방 갖다 드릴게요!**를 선택하면 주문 수량 전부를 진열 재고에서 건네고 개당 가격 × 수량으로 정산합니다. 진열 수량이 부족하면 일부만 판매하지 않고 지급·정산 없이 준비 안내를 표시합니다. **아직 빵이 준비가 안 됐네요.**는 손님을 기다리게 하고, **오늘 그 빵은 더 못 팔아요.**는 돌려보냅니다. 폐점하면 대기 주문이 취소됩니다. 메뉴/대화 중 손님 도착과 게임 시계는 멈추지만 이미 시작한 오븐 굽기는 계속됩니다.

### 서쪽 베리 텃밭
사거리에서 소도시와 **반대 방향인 왼쪽 길 끝**으로 걸으면 베리 텃밭으로 이동합니다. 오른쪽 길 끝으로 돌아옵니다.

- 밭은 6개입니다. 각 밭 아래로 접근해 E를 누르면 관리 창이 열립니다.
- 잡화점에서 산 **베리 씨앗 1개**로 심고 **물 주기**를 누릅니다. 물 주기에는 별도 소모품이 필요 없습니다.
- 물을 준 뒤 **게임 시간 2시간**이 지나면 베리 8개를 수확합니다. 평소 속도로 약 1분이며, 빵집에서 잠을 자고 다음 날 수확해도 됩니다.
- 수확 후 밭은 비어 새 씨앗을 심을 수 있습니다. 씨앗·물주기·성장 상태도 저장됩니다.

### 우체국과 소도시
- 사거리 오른쪽 위 건물은 **달빛 우체국**입니다. 문으로 들어가 **우체국 직원 료와 대화** → **네, 서명할게요.** → 답변을 끝까지 넘기면 소포 수령. 하루 한 번 밀가루 4, 꿀 1을 받습니다.
- 사거리의 오른쪽 길 끝을 걸어가면 **해봄 소도시**입니다. 첨부 이미지에 맞춰 카페·잡화점·마을 회관·공방이 있고, 대화 가능한 주민 3명이 있습니다. 잡화점은 재료 구매, 카페는 커피·디저트 구매와 기력 회복, 공방은 도구 구매와 오븐 개량이 가능하며 마을 회관 내부는 준비 중입니다. 왼쪽 길로 돌아옵니다.
- 기존 주민 세 명과 퀘스트 세 개도 유지됩니다.

## 실내 화면과 기존 세이브
빵집·우체국·잡화점·카페에 들어가면 1인칭 정면 화면이 표시되며 캐릭터 이동은 멈춥니다. 화면 위 물건별 버튼으로 기능을 이용하고, 오른쪽 아래 **광장으로 나가기**로 원래 건물 앞에 돌아옵니다. 판매실/작업실/잡화점에서도 저장할 수 있습니다. 기존 실내 세이브도 불러올 수 있으며, 배경 변경으로 건물 안에 겹친 기존 실외 위치는 안전한 길로 옮깁니다. 소지품·돈·퀘스트는 보존합니다. 현재 저장 포맷은 버전 8입니다. 버전 1/2/3/4/5/6 파일을 불러오면 돈·물품·퀘스트·창고·기존 주문을 보존하고 자동 이관합니다. 새 재료가 없던 세이브에는 이스트 6개·소금 6개·베리 씨앗 2개를 초기 지급합니다. 이후 최신 버전으로 저장하면 다시 지급하지 않습니다. 버전 3에서 옮길 때에는 재료를 재지급하지 않고 반죽·농사·재고를 유지한 채 우체국 방문 기록만 추가합니다. 업데이트 전 saves 폴더를 백업해 두세요.

## 플레이어 이미지와 애니메이션
업로드한 ZIP의 **원본 이미지 두 장을 배포본에 포함**했습니다. 메뉴에서 이미지를 다시 선택할 필요가 없습니다.

- `assets/characters/source/sheet-2.png`: 여러 포즈가 들어 있는 원본. 앞/뒤/오른쪽 대기 자세를 사용하고 왼쪽은 오른쪽의 좌우 반전으로 표시합니다.
- `assets/characters/source/sheet-1.png`: 별도 걷기 원본. 앞/뒤/오른쪽의 핵심 자세 세 장을 골라 내딛기→교차→반대발 내딛기→교차의 4단계 루프(0.4초)로 사용합니다. 상하 이동에는 각각 앞/뒤 걷기가 재생되며, 왼쪽은 오른쪽 루프를 그대로 미러링합니다.
- `player-idle.png`, `player-walk.png`: 캐릭터별 실루엣을 분리한 실행용 아틀라스입니다. 이웃 프레임의 꼬리가 섞이지 않도록 분리하고 머리 중심을 정렬했습니다. 걷기의 붉은 색조를 대기 팔레트에 맞추고 방향별 머리 너비와 몸 높이를 맞춰 정지/이동 간 크기 변화를 줄였습니다.
- `data/playerAnimations.json`: 방향별 프레임·정렬 기준점·재생 속도. 걷기를 멈추면 마지막 방향의 대기 포즈로 바뀝니다.
- 점프는 사용하지 않습니다. 빵 포즈가 있는 원본 넷째 줄은 `reservedBread`로 보관하며, 현재 플레이 중에는 재생하지 않습니다.

원본 파일은 수정하지 않고 보존합니다. `tools/build-player.py`는 실행용 아틀라스를 다시 만드는 개발 도구입니다(Python/Pillow 필요). 이미 생성된 이미지가 포함되어 있으므로 일반 게임 실행에는 Python이나 추가 설치가 필요 없습니다.

이 데모에서는 플레이어 이미지 불러오기·복원·자동 재적용을 제거했습니다. 캐릭터 모델링을 바꾸려면 `assets/characters/player-idle.png`, `player-walk.png`와 `data/playerAnimations.json`을 수정합니다.

## 개발과 수정

실행·설치·저장 형식을 유지하면서 시작/입력/루프, 화면별 UI, 렌더링, 저장, 서버 API, 스타일을 분리했습니다. 긴 한 줄 코드와 JSON도 읽기 쉽게 정리했습니다.

수정할 기능의 담당 파일과 검증 방법은 **[개발 안내](docs/DEVELOPMENT.md)**를 확인하세요. Codex 작업 규칙은 [AGENTS.md](AGENTS.md)에 있습니다.

```sh
npm start       # 게임 실행 (추가 설치 없음)
npm run check   # JavaScript 구문 검사
npm test        # 시스템·서버 API 테스트
```

코드 수정 후 브라우저 새로고침으로 확인합니다. 서버 코드 변경 때만 서버를 재시작합니다. 맵은 960×576 논리 좌표, 캔버스·배경 캐시는 1920×1152를 사용합니다. 화면 크기가 바뀌면 비율을 유지하며 실내 버튼도 비율로 배치합니다.

이미지·음악은 배포본에 포함되어 외부 다운로드가 필요 없습니다. 원본은 보존하고 실행용 캐릭터 아틀라스만 별도 생성합니다. `tools/build-player.py`는 Python/Pillow를 사용하는 선택적 개발 도구이며 일반 실행에는 필요 없습니다. 음악·대화·이미지 경로는 `data/`의 JSON에서 수정합니다.

GitHub에는 코드와 리소스를 올리며 개인 `saves/*.json`은 제외합니다. 새 버전으로 옮길 때 기존 `saves` 폴더를 복사하세요.

## 검증

시스템·서버 API 95개와 JavaScript 구문 검사를 통과했습니다. Chromium에서 직원/손님 대화, 구매·소포·퀘스트, 반죽과 빵 3종, 창고·진열·판매, 농사, 저장/불러오기, 좁은 화면을 확인했습니다. 캐릭터 크기·색감·좌우 반전과 카운터의 손님 가림도 픽셀 검사했습니다.

Windows 직접 실행은 미검증입니다. `launch.bat`와 `게임 실행.bat`은 기존 바이트와 ASCII/CRLF 형식을 유지했습니다.

## 광장 주민과 잡화점 대화 업데이트

- 배달부 **마리아**와 정원사 **이시도로**는 광장에서 첨부 SD 전신으로, 대화에서는 각각의 상반신 PNG로 표시됩니다. 원본 PNG를 그대로 보관하며, SD의 투명 여백·발 위치만 데이터로 지정합니다.
- 마리아: 좋아하는 빵 질문 → 꿀빵 1개 부탁 → 가방에서 전달 시 20G. 빵이 없다는 선택으로 부탁 취소, 굽는 중이라는 선택으로 대기할 수 있습니다. 완료 후 신혼생활·입양·강아지 이야기로 이어집니다.
- 이시도로: 농사 상태에 따라 두 가지 안내 → 베리 3개 부탁 → 전달 시 20G. 완료 후 농사 안부와 잡화점 씨앗 안내가 나옵니다. 씨앗 2개는 기존 시작 물품이며 대화 때마다 추가 지급하지 않습니다.
- 잡화점 세 자매의 이름은 **아리엔·사샤·에리나**입니다. 새 TXT의 가족 이야기, 에리나가 머뭇거리다가 인사하는 단계와 마지막 반응을 반영했습니다. 세 자매의 합동 대사는 한 페이지에, 개별 대사·지문은 줄마다 진행됩니다.
- 주민 대사·선택지는 `data/townStories.json`, 잡화점은 `data/staffStories.json`, 원본 TXT는 `data/source/`에 있습니다.
- 주민의 내부 ID는 그대로입니다. 이름 대신 사용하던 내부 ID를 유지하므로 기존 완료·진행·호감도·물품을 이어갑니다. 진행 중이던 소라의 부탁은 마리아의 꿀빵 부탁으로 표시되며, 이미 완료한 부탁은 다시 지급하지 않습니다.

주민 변경 전용 브라우저 검사는 `tools/check-town-browser.mjs`입니다. 슬롯 3을 잠시 사용한 뒤 원본을 복원하므로 다른 저장 통합 검사와 순서대로 실행하세요. 이번 변경에서는 시스템 테스트 51개, 구문 검사와 관련 Chromium 검사를 실행했습니다. Windows 직접 실행은 확인하지 못했으며 실행 배치 파일은 수정하지 않았습니다.

## 하루의 빛·기력·퇴근과 카페

- 마을·소도시·텃밭은 시간에 맞춰 노란 노을에서 푸른 밤으로 어두워집니다. 오후 **4시에는 노을**, **7시에는 밤**, 새벽 5~6시에는 다시 밝아집니다. 실내 조명은 유지됩니다. 자정은 다음 날 00:00으로 이어지며 자동 수면·기력 회복은 없습니다.
- 새 게임은 **오전 6시 / 기력 100**으로 시작합니다. 반죽을 시작할 때마다 **기력 10**을 한 번만 사용합니다. 기력이 부족하면 재료를 사용하지 않습니다. 이미 시작한 반죽을 다시 열어도 추가 기력은 소모하지 않습니다.
- 빵집 **영업 안내판 → 가게 닫고 퇴근하기 → 잠자기 · 오전 6시에 기상**을 선택하세요. 퇴근 시 문을 닫고 대기 주문을 취소합니다. 재고·진열 빵·수익은 유지됩니다. 수면 창을 닫으면 잠은 자지 않은 채 폐점 상태가 됩니다. 빵집 안에서는 ESC의 **퇴근·잠자기**로도 수면 창을 열 수 있습니다.
- 잠들기 전 예상 수면 시간과 회복량을 표시합니다. **다음으로 오는 오전 6시**까지 자며, 8시간에 최대 100만큼 회복하고 짧게 자면 그 비율만 회복합니다. 남은 기력에 더하되 최대 100을 넘지 않습니다. 예: 정확히 22시에 자면 +100, 자정이면 +75, 새벽 2시면 +50까지 회복합니다. 소수점 회복량은 버립니다. 새벽 2시에 자면 같은 날짜의 6시에 일어나며 날짜를 한 번 더 넘기지 않습니다.
- 오븐에서 굽던 빵은 자고 나면 완성 상태가 되며 직접 꺼내야 합니다. 반죽·토핑 단계는 그대로 유지됩니다. 잠을 자도 자동 저장하지 않으므로 기존처럼 ESC에서 저장하세요.
- 소도시 **왼쪽 위 카페**의 문으로 들어가 **바리스타 데셰네와 대화 → 주문하기**를 선택하세요. 따뜻한 커피는 **8G / 기력 +15**, 베리 케이크는 **12G / 기력 +25**입니다. 구매 즉시 먹으며, 기력이 가득 찼거나 돈이 부족하면 결제하지 않습니다.
- 마리아·이시도로는 빵집에 방문할 때 **SD 캐릭터**로 계산대 뒤에 표시됩니다. **손님과 대화하기**를 누르면 **상반신 초상**으로 대화합니다.
- 세이브 버전 1~4는 돈·재료·퀘스트·기존 시간을 유지하며 최신 버전으로 읽고 기력 100을 초기 부여합니다. 이후 저장·불러오기에서는 남은 기력을 유지하므로 다시 지급하지 않습니다. 패치 적용 전 서버 창을 닫고 새 버전을 실행하세요.

관련 규칙은 `src/wellbeing.js`, 기력 상수는 `src/stamina.js`, 시간별 색감은 `src/render/daylight.js`, 카페 상품은 `data/cafeItems.json`에서 수정할 수 있습니다. `tools/check-wellbeing-browser.mjs`는 시간대 픽셀·자정·퇴근·수면 회복·카페·기력 저장·손님 SD/초상 전환을 확인합니다. 이 검사도 슬롯 3을 잠시 사용하므로 다른 세이브 통합 검사와 순서대로 실행합니다.

## 첨부 카페 배경과 바리스타 대화

- 카페 실내는 첨부 PNG 원본(`assets/backgrounds/interiors/cafe.png`)을 사용합니다. 배경에 직원이 이미 있으므로 같은 인물을 중복으로 덧그리지 않습니다.
- **바리스타 데셰네와 대화**를 누르면 첨부 상반신 초상(`assets/characters/clerks/barista.png`)으로 대화합니다. 글자 출력·스페이스/다음 진행 방식은 다른 직원과 같습니다.
- **주문하기**는 기존 커피·케이크 메뉴를 엽니다. 가격과 기력 회복량은 그대로이며, 메뉴를 닫으면 다음 주문 전에 다시 직원과 대화합니다.
- **말 걸어보기**에서 크레마의 행방, 다른 메뉴·브런치 제안, 바라보기의 세 단계와 그만하기를 선택할 수 있습니다. 원문의 선택지 복귀를 유지했습니다.
- **카페 나오기**는 작별 대사를 끝까지 넘긴 뒤 건물 밖으로 이동합니다. **아무것도 아니에요.**는 바로 나가고, ESC/닫기는 대화만 취소하여 카페에 머뭅니다.
- 원본 TXT는 `data/source/barista-dialogue.txt`, 대사와 분기는 `data/staffStories.json`의 `cafe`, 직원 정보는 `data/serviceDialogues.json`의 `staff.cafe`에 있습니다. 현재 저장 형식은 버전 7이며 카페 방문 상태도 이어집니다.

`tests/cafeStory.test.js`와 `tools/check-cafe-browser.mjs`가 원문 포함·전체 분기·주문·취소·퇴장·기력·저장·작은 화면을 검사합니다. 브라우저 검사는 슬롯 3 원본을 복원하며 다른 저장 통합 검사와 순서대로 실행합니다. 이번 수정에서 테스트 66개와 구문 검사, 카페 브라우저 검사를 통과했습니다. Windows 직접 실행은 미확인입니다.

## 글자 출력에 맞춘 캐릭터 목소리

- 첨부 MP3 7개를 마리아·이시도로·데셰네·우체국 직원 하나·아리엔·사샤·에리나에게 연결했습니다. 대사가 자연스럽게 한 글자씩 나타날 때마다 해당 샘플의 짧은 소리 조각을 재생합니다. 원본 MP3는 바꾸지 않았습니다.
- 말줄임표(`....`, `…`), 공백·구두점·화자 이름표와 나레이션은 무음입니다. 세 자매가 한 페이지에서 말할 때는 `아리엔:`, `사샤:`, `에리나:` 뒤의 대사에 맞춰 샘플이 바뀝니다. 별도 이름이 없는 `sam (1).wav`는 `assets/audio/voices/source/`에 보관하고 캐릭터에 임의 배정하지 않았습니다. 샘플이 없는 주민도 무음입니다.
- 스페이스/다음으로 대사를 한 번에 표시해도 건너뛴 글자의 소리를 몰아서 재생하지 않습니다. 줄 전환·선택지 클릭·대화 종료·ESC·탭 숨김 시 남은 소리를 멈춥니다. 음량과 음소거는 기존 **♫ 음악** 설정을 따릅니다.
- 첫 클릭/키 입력 후 샘플을 한 번 읽고 캐시합니다. 소리 조각은 겹치지 않게 짧은 페이드와 함께 재생합니다. 브라우저가 오디오를 허용하지 않거나 파일을 읽지 못해도 대사·선택지·게임 진행은 계속됩니다.
- 매핑은 `data/voices.json`, 샘플은 `assets/audio/voices/`, 글자별 화자 판별·버퍼 캐시·재생은 `src/dialogueVoice.js`에서 관리합니다. 대화 데이터에서 `kind: "narration"` 또는 `speaker: "이야기"`로 지정하면 목소리를 내지 않습니다. 새 목소리는 MP3와 별칭 매핑을 추가하면 됩니다.
- `tests/dialogueVoice.test.js`와 `tools/check-voices-browser.mjs`로 일곱 파일의 실제 디코딩·글자별 Web Audio 재생·화자 전환·무음·건너뛰기·중단을 검사했습니다. 브라우저 검사는 슬롯 3을 임시 사용한 뒤 원본을 복원하므로 다른 저장 통합 검사와 순서대로 실행합니다. Windows에서 직접 청취하는 검증은 수행하지 않았습니다.

저장 형식과 실행·설치 방법은 그대로입니다. 추가 패키지를 설치할 필요가 없습니다.

## 세 자매 음량·일괄 오븐 패치

아리엔·사샤·에리나의 목소리만 개별 배율을 **2배**로 높였습니다. 다른 캐릭터와 배경음악의 배율은 바꾸지 않았으며 기존 공통 음량·음소거 설정을 따릅니다. MP3 원본은 유지합니다. 배율은 `data/voices.json`에서 조정합니다.

세이브 버전 6부터 `baking`은 치대는 반죽, `doughs`는 종류별 준비 반죽, `oven`은 최대 6개짜리 판과 굽기 경과 시간을 저장합니다. 버전 1~5도 불러올 수 있습니다. 구버전에서 치대는 중·토핑 선택 중이면 진행도를 그대로 유지합니다. 토핑까지 고른 반죽은 준비 반죽 1개로 옮기고, 굽는 중이면 기존 완료 비율을 60초 기준으로 환산합니다(예: 이전 2/5초 → 24/60초). 이미 완성된 빵은 즉시 꺼낼 수 있습니다. 돈·물품·퀘스트·기력·완성 빵은 보존하고 이관 시 재료를 다시 차감하지 않습니다.

`tests/batchBaking.test.js`와 `tools/check-batch-browser.mjs`로 혼합 6개·초과 차단·실제 60초 타이머·동시 반죽·저장 복원·창고·판매·수면·이관·작은 화면·세 자매의 실제 오디오 게인을 확인합니다. 브라우저 검사는 슬롯 3을 임시 사용한 뒤 복원하며 다른 저장 통합 검사와 순서대로 실행합니다. Windows 직접 실행·청취는 미확인입니다.

## 파이·쿠키와 새 손님

기존 빵 3종에 파이 3종과 쿠키 3종을 더해 총 9종을 만들고 판매합니다. 새 재료는 잡화점에서 개별 구매하며, 새 메뉴용 재료를 패치 때 임의로 지급하지 않습니다.

| --- | --- | --- | ---: |
| 빵 | 밀가루 2·이스트 1·소금 1 | 없음 → 밀빵 / 꿀 1 → 꿀빵 / 베리 2 → 베리빵 | 16 / 25 / 30G |

**오븐 관리 → 베리 말리기**에서 생베리 2개당 말린 베리 1개를 만듭니다. 1~6묶음을 60초 동안 건조하고 **말린 베리 꺼내기**로 가방에 받습니다. 건조와 굽기는 같은 오븐을 사용하므로 동시에 할 수 없습니다. 건조 경과 시간도 저장하며, 말린 베리는 구운 제품 창고가 아닌 재료 가방에 들어갑니다.

우체국 직원 료, 아리엔·사샤·에리나, 카페 데셰네와 공방 소마·크레마토리도 손님으로 방문합니다. 기존 미라·이시도로·마리아와 합해 10명이 차례로 방문하며, 제품과 수량은 방문할 때마다 새로 정합니다. 고양이 모티브인 마리아·료·소마·세 자매는 생선파이를, 곰 수인 이시도로는 미트파이를 더 자주 고릅니다(기본 가중치 1, 선호 4). 다른 제품도 주문할 수 있습니다. 주문은 저장·불러오기나 대화를 다시 열어도 재추첨하지 않습니다. 새 주문 대사는 원래 캐릭터의 말투에 맞췄고 기존 대화·퀘스트는 유지합니다.

첨부 SD는 `assets/characters/visitors/`에 원본 그대로 보관합니다. 세 자매는 파일명 순서대로 왼쪽 아리엔·가운데 사샤·오른쪽 에리나 영역을 사용합니다. 손님별 SD 영역·초상·선호도는 `data/customers.json`, 주문·감사·대기·거절 대사는 `data/serviceDialogues.json`에서 수정합니다. 대화에서는 기존 상반신 초상과 목소리를 사용합니다.

판매실 배경은 `assets/backgrounds/interiors/stocked-bakery.png`이며 음식 스프라이트를 덧그리지 않습니다. 그림이 가득 차 있어도 실제 판매 가능 수량은 **화면 아래 진열 재고**를 따릅니다. 패널에서 영업 상태·누적 수익·현재 손님과 수량을 확인하고, **진열·재고 관리**에서 개수를 입력해 진열하거나 가방으로 회수할 수 있습니다. 창고에서 꺼내는 기존 방식은 유지합니다.

저장 버전 7은 새 재료·제품·반죽 종류·오븐 건조·주문 수량을 저장합니다. 버전 1~6은 기존 돈·기력·물품·진행·오븐을 보존해 이관합니다. 이전 작업 반죽은 빵 반죽으로, 이전 주문은 1개 주문으로 이어지며 새 종류 수량은 0으로 시작합니다.

`tests/pastries.test.js`와 `tools/check-expansion-browser.mjs`가 전 레시피·건조·확률 선호·수량 판매·직원 방문·이미지·새 UI·이관을 검사합니다. 브라우저에서 실제 60초 건조, 여섯 새 메뉴의 마우스 반죽, 혼합 굽기와 수면 후 수령, 8명 방문·초상, 3개 정산과 작은 화면을 확인했습니다. 전체 테스트 95개와 구문 검사가 통과했으며 Windows 직접 실행은 미확인입니다.
